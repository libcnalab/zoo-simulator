# Zoo Simulator in the browser

The game builds for the web with Emscripten through cna-engine's `cna_engine_add_game()`:
one page, the wasm, and the assets and data definitions as one preloaded package. CNA draws
through its `WEBGL2` renderer (EasyGL over WebGL 2), the default under Emscripten.

## Building

emsdk 6.0.9 is installed in `~/emsdk`. On the owner's machine the CNA libraries come from the
snapshot `~/deps/zoo-libcna/` (README "Building"); the browser build uses the same paths, with
the Emscripten SDL3 cache beside the native one in the snapshot (generated by CNA's configure,
reused by every later configure):

```bash
source ~/emsdk/emsdk_env.sh
export CCACHE_DIR=/rv/cnaccache CCACHE_BASEDIR=/rv
D=~/deps/zoo-libcna
emcmake cmake -S . -B build-probe/web -G Ninja -DCMAKE_BUILD_TYPE=Release -DZOO_BUILD_TESTS=OFF \
  -DZOO_LIBCNA_ROOT=$D -DCNA_ENGINE_ROOT=$D/cna-engine \
  -DZOO_SHARP_RUNTIME_ROOT=$D/sharp-runtime -DZOO_NLOHMANN_JSON_INCLUDE=$D/sharp-runtime/vendor \
  -DZOO_GOOGLETEST_DIR=$D/sharp-runtime/vendor/googletest -DCNA_EASYGL_ROOT=$D/easy-gl \
  -DCNA_ENGINE_CNA_DIR=$D/cna -DCNA_ENGINE_EXTENDED_DIR=$D/cna-extended \
  -DCNA_ENGINE_SHARP_RUNTIME_DIR=$D/sharp-runtime -DCNA_SHARP_RUNTIME_ROOT=$D/sharp-runtime \
  -DCNA_GAMER_SERVICES_SERVER_ROOT=$D/cna-gamer-services-server \
  -DCNA_SDL_PREBUILT_ROOT=$D/cna/.sdl-prebuilt-emscripten \
  -DCMAKE_CXX_COMPILER_LAUNCHER=ccache -DCMAKE_C_COMPILER_LAUNCHER=ccache
cmake --build build-probe/web --target zoo-simulator --parallel 2
```

The build tree is `build-probe/web/`: the closed list of build directories in `../CLAUDE.md`
has no web entry, and a new top-level `build-web/` would need the owner's word.

The page and its files are gathered in `build-probe/web/web-package/` (`index.html`,
`zoo-simulator.{html,js,wasm,data}`). Serve that directory over HTTP (a page opened as `file:`
does not work); `.wasm` must be served as `application/wasm`:

```bash
cd build-probe/web/web-package && python3 -m http.server 8000
# then http://localhost:8000/ in Chrome
```

## Rebuilt (2026-11-24)

The current WebGL 2 package was rebuilt successfully with `CCACHE_DISABLE=1` and two parallel
jobs after the apocalypse responsiveness fixes, expanded estate and final ground-detail work.
Ninja compiled the changed game sources and linked `zoo-simulator.html`. The resulting package
contains:

| file | bytes |
|---|---:|
| `zoo-simulator.html` | 3,067 |
| `zoo-simulator.js` | 300,424 |
| `zoo-simulator.wasm` | 37,235,051 |
| `zoo-simulator.data` | 215,381,022 |

Static verification identifies the wasm as a version-1 WebAssembly module. The generated HTML
references `zoo-simulator.js`, whose loader references the `.data` and `.wasm` payloads. This
rebuild was not launched in a browser; serve `web-package/` for the final interactive smoke test.

## What differs in the browser

- `data/` is preloaded at `/data` beside `/assets` (`src/game/CMakeLists.txt`); the avatars of
  the visitors are compiled into CNA's Gamer Services and need no preload.
- No threads: CNA's Wasm is built without pthreads, so the ground is painted on one thread
  (`TerrainRenderer.cpp`), which makes the loading longer than on the desktop.
- Saves and preferences live in the page's in-memory file system and are gone when the page
  is closed.
- `std::chrono::clock_cast` is missing from libc++: the save list converts a file's time through
  "now" on both clocks (`VisitorHud.cpp`).

## Tried (2026-11-14)

The first build took 31 minutes at two jobs (853 steps, CNA compiled for Wasm for the first
time; the shared ccache now holds it); a rebuild after a game change takes about a minute. The
package is 126 MB: `zoo-simulator.wasm` 36 MB, `zoo-simulator.data` (assets and data) 95 MB.

It was run in headless Chrome (`--use-angle=gl-egl --ozone-platform=headless`, the machine's
GPU through EGL; SwiftShader through Vulkan found no display) and driven over the DevTools
protocol: the title, a click on *Visit Zoo*, the walk, `B` for the binoculars, `M` for the map
and a click on a place of the map, each looked at on a screenshot. Everything answered as on the
desktop. From the console of four runs, with the machine shared with other agents:

| | browser | desktop |
|---|---:|---:|
| Building the zoo | 1.1 to 2.7 s | 0.8 to 1.2 s |
| The morning's visitors (6,000 steps) | 2.2 to 5.5 s | 2.1 to 4 s |
| Painting the ground (one thread) | 7.0 to 18.4 s | 2.4 s |
| From the page's load to the title | 35 to 107 s | |

The frame rate of the game in the browser was not measured (the page's own animation frames
ran at 30 a second in headless Chrome, which says nothing about a real window). Nobody has
played it in a visible browser, with a real mouse (pointer lock) or with sound; Firefox and
Safari were not tried.
